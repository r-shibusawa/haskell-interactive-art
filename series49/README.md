# シリーズ49：最適化理論 ─ Haskell コード集

坂を下る速さを、計算で確かめる。凸性と最適性条件から、最急降下法・直線探索・慣性とネステロフの加速・確率的勾配法と Adam、ニュートン法・BFGS・共役勾配法、ラグランジュ乗数・KKT 条件・ペナルティ法と内点法、LASSO・非凸と鞍点・最速降下線まで、本物の関数と本物の勾配で計算し、収束率の理論値と実測を並べるコード集です。p5.js 版と同じ計算を Haskell（gloss）で書き直しました。誤差を 10⁻¹⁰ より小さいところまで測るので、計算はすべて `Double`（倍精度）で行い、描くときだけ `Float` にしています。どのスケッチも起動時に p5.js 版と同じ自己テスト（知られている答え・理論の収束率との照合）を行い、結果を端末と画面の左下に出します。

p5.js 版：https://r-shibusawa.github.io/p5-interactive-art/series49/

## 使い方

```
cabal run s49-00
```

番号を変えると別のスケッチが動きます（`s49-01`、`s49-15` など）。どのスケッチも一番下に「最適化の道具」（テスト関数・等高線・対数グラフ・自己テスト）が入っています。

## p5.js 版との違い

- **画面の文字**：gloss のフォントは日本語を出せないので、説明は短い英語です。記号は ASCII で書きます（κ は `kappa`、λ は `lambda`、∇f は `grad f`、x² は `x^2`、10⁻⁸ は `1e-8`、「発散」は `diverged`、✓ は `OK`）。
- **自己テスト**：p5.js 版と同じ項目・同じ許容誤差で、全 16 本で合計 184 項目を照合します。結果は端末に出し、画面の左下に `Self-test OK 28 / 28` のように合格数を表示します（テストモードでは失敗した項目とまとめの 1 行だけを出します）。
- **数の精度**：計算はすべて `Double` で、描くときだけ `Float` にします（NaN は 0、とても大きい値は ±10⁵ に切りつめて描きます）。
- **等高線**：p5.js 版と同じく関数を変えたときだけ計算します。段の色ぬりはピクセル画像（8 万画素以下になるよう 2.5 倍などに拡大）、線はマーチングスクエアの線分を辺でつないで長い折れ線にしてから描きます。00 の 2 次元でヘッセ行列が負の固有値をもつ場所（ピンク）は、この色ぬりの画像に重ねて塗ります。
- **太い線**：gloss の線は細いので、反復の軌跡や対数グラフの線は、細い線を少しずつずらして重ねて太く見せます。点線は自分で区切って描きます。gloss の `Polygon` は凸の形しか正しく塗れないので、00 のエピグラフなどは細い帯に分けて塗ります。
- **03 直線探索**：ウルフ条件の探索で t を 2 倍にしていく所に、勾配が 0 や異常値なら動かない、という守りを入れました（14 と同じ考え方）。t の上限 1 は付けていません（t = 1 から始めて広げる探索なので、上限を付けると広げられなくなるため）。
- **05 確率的勾配法**：ロジスティック回帰の損失は 1 点ごとに 120 個の exp・log を使うので、等高線はデータを変えたとき数フレームに分けて計算し、そろってから表示します（一瞬おくれて出ます）。学習率やバッチを変えただけなら作りなおしません。12 個のミニバッチに分ける自己テストの並べかえは、p5.js 版の「ランダムな比較での sort」の代わりにフィッシャー–イェーツ法（種 5）で行います（結果は並べ方によりません）。
- **13 非凸と鞍点**：引き込み領域の色分けは 1 フレーム 5 ms ずつ計算し、行ごとに同じ色の区間を半透明の長方形で重ねます。
- **14 最速降下線**：着いた順の音は Art.Sound の `playTone` で 1 音ずつ鳴らします（クリックしなくても鳴ります）。
- **15 カメラ**：カメラは ffmpeg 経由で 160×120 で読みます（左右の反転はライブラリ側で済んでいます）。カメラが無いか真っ暗なときはテスト画像を使います。軌跡は 320×200 のバッファにためて 4 倍に拡大して表示するので、p5.js 版の細い線より少しあらく見えます。`S` の保存は SVG です。
