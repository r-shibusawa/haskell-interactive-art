# シリーズ63：強化学習 ─ Haskell コード集

正解を教えてもらわずに、**報酬だけを手がかりに試行錯誤で行動を学ぶ** ― 強化学習のコード集です。スロットマシンの「探索と活用」から始めて、マルコフ決定過程とグリッドワールド、価値反復・方策反復、モンテカルロと TD 学習、Q 学習と SARSA（崖歩き）、探索の工夫、タイルコーディングで山登り車、モデルを使う Dyna-Q、方策勾配 REINFORCE、小さなニューラルネットの Q 学習（経験再生とターゲットネットワーク）、三目並べの自己対戦、報酬の設計と「ずる」、そして人が耳や体で報酬を与える学習まで、どれも**機械学習のライブラリを使わずにゼロから計算した**シミュレーションです。p5.js 版と同じ計算（ε-greedy・UCB1・トンプソン抽出、価値反復・方策反復、MC と TD(0)、Q 学習と SARSA、タイルコーディング、Dyna-Q / Dyna-Q+、REINFORCE、手書きの誤差逆伝播と Adam、アフターステートの TD 学習、ポテンシャル整形、勾配バンディット）を Haskell（gloss）で書き直し、計算は倍精度（`Double`）、Q 表やネットの重みは unboxed ベクトルで持ちます。乱数は p5.js 版と同じ種つきの mulberry32 で、引く順番もそろえてあるので、同じ種なら学習の結果も p5.js 版と同じです。

p5.js 版：https://r-shibusawa.github.io/p5-interactive-art/series63/

## 使い方

```
cabal run s63-00
```

番号を変えると別のスケッチが動きます（`s63-01`、`s63-15` など）。どのスケッチも一番下に「強化学習の道具」（種つきの乱数、グリッドワールドとマルコフ決定過程、グラフ、自己テストなど）が入っています。学習は 1 フレームに数ミリ秒ずつ進めるので、画面は止まりません。**F キーで速さ**を変えられます。記号：状態 s、行動 a、報酬 r、割引率 γ（画面では `gamma`）、価値 V(s)、行動価値 Q(s, a)、方策 π（`pi`）、学習率 α（`alpha`）、探索の割合 ε（`eps`）。🔊 音を使うスケッチ（14）は Art.Sound で鳴らします。**音量は小さめから**（全体の音量 `master` は 0.2 以下）。📷 カメラ（15）はカメラがなくてもマウスのクリックで動きます。

## p5.js 版との違い

- **画面の文字**：gloss のフォントは日本語やギリシャ文字を出せないので、説明は短い英語で、記号は ASCII で書きます（γ は `gamma`、ε は `eps`、α は `alpha`、π は `pi`、✓ は `OK`）。地図の「宝」「穴」は `G`・`P`（06 の崖も `P`）です。グラフの目盛りの文字は 12 px から 14 px に大きくしました。
- **自己テスト**：p5.js 版と同じ項目・同じ許容誤差・同じ種・同じ乱数の順で照合します（16 本で全部 78 項目。00 から順に 5・6・5・5・5・5・4・5・5・4・5・5・5・5・5・4）。項目の名前に出る数（後悔の平均、収束までの回数、学習後の歩数、キャッチの成功率 91% など）も p5.js 版と同じになります。結果は起動時に端末に出し、画面右下にも `Self-test OK 5 / 5` のように合格数を表示します（テストモードでは失敗した項目とまとめの 1 行だけを出します）。
- **乱数**：p5.js 版の `rnd()`（mulberry32）を 32 ビットの整数でそのまま書き直し、乱数を順に引く小さなモナド `R` で、p5.js 版と同じ順番に引きます。重い学習（09 の Dyna-Q の計画、12 の自己対戦）は ST の中で同じ乱数の列を使います。03 は p5.js 版と同じく、自己テストのあとの乱数の状態から続けます。
- **矢印キー**：p5.js 版と同じく ↑↓ ← → で γ・すべりやすさ・α・感度などが変わり、14 は ↑ で好き、↓ できらいを返せます。
- **1 フレームの計算時間**：p5.js 版の `performance.now()` で区切る学習は、`sliced`（`GHC.Clock` で同じミリ秒の予算）で書き直しました。p5.js 版の `while` とちがい、1 フレームに最低 1 回は必ず動きます（06 の「速い」は p5.js 版より 1 歩多く進むことがあります）。10 の「速い」は 8 ミリ秒から 6 ミリ秒にしました。
- **記録の上限**：メモリを増やし続けないように、エピソードの記録は上限つきです（05・06・13 は 10 万件、08・09・11 は 2 万件、14 の報酬の履歴は表示する最近 60 回、15 は 3000 回）。上限を超えると、グラフの横軸は直近の分になります。07 は最初の 41 エピソードの歩数（グラフと自己テストに使う分）とエピソードの数だけを持ちます。10 の画面に出さない履歴（hist）は省きました。
- **表の持ち方**：Q 表・価値・ネットの重みは unboxed ベクトルです。11 のネットの重みは 1 本のベクトル（W1 | b1 | W2 | b2）に並べ、ターゲットネットワークは値のコピー（Haskell の値は書きかわらないので、自己テストの「別の配列」は「学習で本体が変わってもターゲットはそのまま」を確かめます）。12 の価値の表は p5.js 版の Map の代わりに 3^9 = 19683 マスの配列で、「表にない盤面」を NaN で表します（結果は同じ）。13 の価値反復はマス × 向きの移動先と報酬を前もって表にします（式と更新の順は同じ）。
- **表示の細かい違い**：01 の遷移確率の表は、報酬が 1 歩の報酬と違う行き先だけ r を書きます。04 のエピソードの道は、長いときに前を `...` で省きます。08 のコストの地形は小さなピクセル画像です。
- **14 耳で報酬を与える**：Web Audio の代わりに Art.Sound の `playTone` で 1 音ずつ鳴らします（音の予約は別スレッドの待ち時間で、全体の音量 `master` = 0.12）。発音までに少し遅れがあります。次のフレーズまでの 0.4 秒（`setTimeout`）は時刻で待ちます。
- **15 体で報酬を与える**：カメラは Art.Device（ffmpeg 経由、64 × 48、左右反転）で読み、本物の映像が来ているときだけフレーム差分を報酬にします（カメラがないときの合成映像では報酬を出さず、p5.js 版と同じくマウスのクリックが報酬）。`S` の保存は PNG ではなく SVG です。
