# シリーズ70：隠れマルコフモデル ─ Haskell コード集

**見えない状態がマルコフ連鎖で動き、見えるのはそこから出た観測だけ。** その「見えないもの」を推し量る ― 隠れマルコフモデル（HMM）を自分で動かして確かめるコード集です。かさだけを見て天気を当てる生成モデルから始めて、尤度と前向きアルゴリズム、フィルタリング、ビタビの最尤経路、平滑化と予測、バウム-ウェルチ（EM）による学習、アンダーフローとスケーリング、状態数の選び方、正規分布を出す HMM、左から右への HMM によるジェスチャ認識、滞在時間と隠れセミマルコフモデル、ペア HMM と配列アラインメント、品詞タグ付け、DNA の領域さがし、そして音とカメラまで、どれも**ライブラリを使わずにアルゴリズムをゼロから実装し、短い列では N^T 本の道の総当たりと答えが一致することを確かめる**スケッチです。p5.js 版と同じアルゴリズム（(π, A, B) からのサンプリング、そのまま・毎時刻の正規化つき・log-sum-exp の前向き後ろ向き、予測 → 更新のフィルタと k 歩先の予測、平滑化 γ と ξ、固定ラグ平滑化、戻り矢印つきの対数ビタビと事後復号、複数の観測列のバウム-ウェルチとラベルの入れかえ、BIC・AIC と検証データの対数尤度、正規分布の EM、左から右への HMM、HSMM の前向き、3 状態のペア HMM とアフィンギャップの Needleman–Wunsch、数えて作る品詞タグ付け、2 状態の DNA の領域分け）を Haskell（gloss）で書き直しています。計算はどれも Double（倍精度）で、種つきの乱数も p5.js 版と同じ列を同じ順に引くので、画面に出る列や学習の結果は p5.js 版と同じになります。

p5.js 版：https://r-shibusawa.github.io/p5-interactive-art/series70/

## 使い方

```
cabal run s70-00
```

番号を変えると別のスケッチが動きます（`s70-01`、`s70-15` など）。どのスケッチも一番下に「HMM の道具」（サンプリング、前向き・後ろ向き（そのまま・スケーリング・対数）、ビタビ、平滑化、バウム-ウェルチ、総当たり、グラフを描く道具、種つきの乱数、自己テストなど）が入っています。

記号：モデル `Hmm { hP0, hTr, hEm }` ＝ はじめの分布 π、遷移行列 A（`hTr !! i !! j` = 状態 i の次に j、各行の合計 = 1）、出力行列 B（`hEm !! j !! k` = 状態 j が記号 k を出す）。画面では α β γ ξ δ π を `alpha` `beta` `gamma` `xi` `delta` `pi` と書きます。

学習（05・07・08・13）は 1 フレームに少しずつ進めるので、画面は止まりません。🔊 音を使うスケッチ（14）は **音量を小さめから**（全体の音量は 0.2 以下）。📷 カメラ（15）はカメラがなくてもマウスの動きで動きます（C で切りかえ）。

## p5.js 版との違い

- **画面の文字**：gloss のフォントは日本語やギリシャ文字・記号を出せないので、説明は短い英語で、記号は ASCII で書きます（α β γ ξ δ ε は `alpha` `beta` `gamma` `xi` `delta` `eps`、∞ は `inf`、→ は `->`、✓ ✗ は `OK` `x`、入力のカーソル ▏ は `_`、▶ は `>`）。状態や観測の名前も英語です：00 の晴れ・くもり・雨は sunny / cloudy / rainy（丸の中は S C R）、かさなし・かさありは none / umbrella、01 の猫は sleepy / playful / hungry と quiet / purr / meow（2 匹は lazy cat / wild cat）、03 は asleep / cooking / gaming と quiet / clatter / laughter（03 の丸の中の γ は `g 0.xx`）、04 は normal / faulty と good / defective、05 は lively / tired と peep / tweet / quiet、07 の注文は coffee / tea / juice / cake / sandw、08 は calm / stormy、09 のジェスチャは circle / triangle / Z / L（8 方向の記号は小さな矢印、B の列の名前は E SE S SW W NW N NE）、12 の品詞は det / noun / verb / adj / prep / pron / adv（1 文字の D N V A P R B はそのまま）、13 は bg / isle、14 のドレミは do re mi fa sol la ti do+、15 は away / sitting / moving と still / a little / a lot。文字は 14 px より小さくしないので（p5.js 版は所により 9〜13 px）、長い説明は短くしたり 2 行に分けたりし、狭いマスの数字は出しません（11 のマスの事後確率は 40 px より大きいときだけ、12 の Tab の出力表は単語が 7 個以上のとき色だけ）。10 の目盛りの「19」は「20+」と重なるので省きます。11 の並べた文字列は、gloss のフォントが等幅でないので 1 文字ずつ 18 px おきに置きます。パネルやマスの角は丸くありません。
- **自己テスト**：p5.js 版と同じ項目・同じ許容誤差・同じ種で照合します（全部で 145 項目：00 から順に 9・8・10・9・10・8・10・9・9・9・9・9・10・9・8・9）。項目の名前も p5.js 版と同じで、名前に入る数（05 の対数尤度、09 の 60 / 60 など）も同じになります。結果は起動時に端末に出し、画面の右下にも `Self-test OK 9 / 9` のように合格数を出します（テストモードでは失敗した項目とまとめの 1 行だけ）。
- **乱数**：p5.js 版の `rnd()`（mulberry32）を 32 ビットの整数でそのまま書き直し、乱数の列を 1 本だけ持って引く順番もそろえた（乱数を順に引く小さなモナド `R`）ので、サンプルの列、バウム-ウェルチの出発点、07 で BIC が 3 状態を選ぶこと、09 の 60 個のジェスチャの判定、13 の DNA 列、11 の R で作る文字列の組などは p5.js 版と同じです。p5.js 版で `draw()` の中にある時間の進み（新しい観測、毎フレームの学習など）は `skStep` で同じ順に行います。
- **計算**：どれも Double で、足し算の順番も p5.js 版と同じにしています。06 で、スケーリングしない前向きの値が長い列で 0 になる（アンダーフロー）のも同じです。09 の学習（C で 4 つのモデルを学び直す）は速さのために unboxed ベクトルで書いたバウム-ウェルチを使います（足す順番は同じで、結果はキットの版とぴったり同じ）。
- **07 状態はいくつ？**：p5.js 版と同じく 1 フレームに約 6 ミリ秒ぶん学習を進めます（1 フレームに 400 回まで）。そのため学習の進み方の速さはコンピュータによってちがいますが、結果は同じです。
- **キー**：gloss ではスペース・Enter・Backspace・Tab・矢印は特別なキーとして届くので、入力欄ではそれを文字の操作に直して扱います（Mac の delete キーも Backspace）。11 は A C G T（大文字でも小文字でも）が入力で、R・矢印・Tab・クリックは p5.js 版と同じ。12 は文字キー・`'`・スペースがいつも入力で（大文字は小文字にする）、Esc はウィンドウを閉じてしまうので、p5.js 版の Esc（全部消す）は **Shift + Backspace** です。ほかのキーと矢印は p5.js 版と同じです。
- **14 見えない和音とメロディ**：Web Audio の代わりに Art.Sound の `playTone` を使います（メロディは三角波 0.45 秒・音量 0.6、和音は正弦波 3 音 0.6 秒・音量 0.22 ずつ。どれも全体の音量 `master` = 0.12 を掛けます）。先読みの予約はできないので、経過時間 `envTime` で数えて `skStep` から鳴らします（少し遅れます）。p5.js 版のクリックは音を始めるだけなので、Haskell 版ではクリックの操作はありません。
- **15 カメラ**：カメラは Art.Device（ffmpeg 経由、64 × 48、左右反転）で読み、明るさは unboxed ベクトルで持ちます。カメラがないときや C で切ったときは、p5.js 版と同じくマウスの動く速さを動きの量にします。`S` の保存は PNG ではなく SVG です。
