# シリーズ66：オートマトン ─ Haskell コード集

状態と遷移だけでできた「計算する機械」― **オートマトン**を自分で描いて、動かして、確かめるコード集です。自動販売機と信号機の状態機械から始めて、DFA の設計、NFA と部分集合構成、DFA の最小化、正規表現から NFA へ（トンプソン構成）、積の構成と言語の演算、ポンピング補題ゲーム、字句解析器、スタックつきのプッシュダウンオートマトン、文脈自由文法と CYK 構文解析、チューリング機械、忙しいビーバーと停止問題、ゲームの敵キャラの状態機械、エイホ-コラシック法、そして音とカメラまで、どれも**ライブラリを使わずに本当に計算した**シミュレーションです。p5.js 版と同じアルゴリズム（ε 閉包つきの NFA のシミュレーション、たどれる集合だけを作る部分集合構成、ムーアの分割の精密化、積の構成と幅優先探索による空言語・同値の判定、再帰下降の正規表現パーサとトンプソン構成、最長一致の字句解析、PDA、CYK、チューリング機械、2 状態の機械 20736 個の分類、階層的な状態機械、トライと失敗リンク）を Haskell（gloss）で書き直しています。状態の番号は p5.js 版と同じく「見つけた順」につけ、種つきの乱数も同じ列を同じ順に引くので、画面に出る機械や数は p5.js 版と同じになります。

p5.js 版：https://r-shibusawa.github.io/p5-interactive-art/series66/

## 使い方

```
cabal run s66-00
```

番号を変えると別のスケッチが動きます（`s66-01`、`s66-15` など）。どのスケッチも一番下に「オートマトンの道具」（DFA・NFA・部分集合構成・最小化・積の構成、正規表現の構文解析とトンプソン構成、状態遷移図の描画と編集、チューリング機械、種つきの乱数、自己テストなど）が入っています。図の読み方：円 = 状態、二重丸 = 受理状態、左から入る矢印 = 開始状態、矢印のラベル = 読む記号、点線（ラベル `eps`）= ε（文字を読まずに進む）。オレンジ = いまいる状態。

文字を入力するスケッチ：01・02・05・08・09・14 は記号のキー（0 1 / a b / かっこ / n + * ( )）がそのまま入力。04 は文字キーがいつも入力で、Tab は正規表現 ⇔ テキストの欄の切りかえ（お手本は ↑↓）。07・13 は **Tab で編集モード**に切りかえてから入力します（編集中は文字キーがすべて入力になり、ほかの操作キーは効きません。13 は Enter でも見るモードに戻ります）。🔊 音を使うスケッチ（14）は Art.Sound で鳴らします。**音量は小さめから**（全体の音量 `master` は 0.2 以下）。📷 カメラ（15）はカメラがなくてもマウスで動きます（C で切りかえ）。

## p5.js 版との違い

- **画面の文字**：gloss のフォントは日本語や記号を出せないので、説明は短い英語で、記号は ASCII で書きます（ε は矢印のラベルでは `eps`、構文木や空の文字列では `e`、≤ は `<=`、○ × は `o` `x`、止 / ∞ は `H` / `oo`、← → ↑ ↓ は `< > ^ v`、⇔ は `<->`）。状態やトークンの名前も英語です（00 の信号は car G / pushed / car Y / walk G / blink、07 の種類は keyword / name / number / op / comment / error、10 の状態は right / carry、read / aR / bR / aChk / bChk / back、12 の状態は Patrol / Spot / Chase / Lost / Search / Flee、13 の根は `^`、14 の高いドは HiDo）。文字は 14 px より小さくしないので、長い説明は短くしたり行を分けたりしています。04 で状態が 30 をこえる NFA は矢印のラベルを省き、長い構文木の文字列は「...」で切ります。パネルの角は丸くありません。
- **自己テスト**：p5.js 版と同じ項目を照合します（全部で 88 項目）。結果は端末に出し、画面右下にも `Self-test OK 7 / 7` のように合格数を表示します（テストモードでは失敗した項目とまとめの 1 行だけを出します）。JavaScript の RegExp を使っていた比べる相手は、自分で書いた別の方法にしました：04 は構文木から「どこで終われるか」の位置の集合を計算する照合器（でたらめな正規表現は文字列と同じ意味の構文木を同じ乱数の順でいっしょに作るので、構文解析も確かめられます）、07 は形ごとに一番長く読む手書きの字句解析、08 は「() [] {} を消し続ける」手書きの削除、06 の言語の判定も手書き、15 は「どれかの身ぶりで終わるか」を調べます。
- **乱数**：p5.js 版の `rnd()`（mulberry32）を 32 ビットの整数でそのまま書き直し、1 本の乱数の列を同じ順に引くので、03 のでたらめな DFA、06 の p、10 の新しい入力、14 のでたらめな入力などは p5.js 版と同じになります。
- **キー**：gloss ではスペース・Enter・Backspace・Tab は特別なキーとして届くので、入力欄では文字に直して扱います（Mac の delete キーも Backspace）。01 の Esc（名前待ちの矢印の取り消し）は、gloss ではウィンドウを閉じることがあります。
- **01 DFA を設計する**：p5.js 版と同じく、最初のクリックは何もしません（ブラウザでキーを届かせるためのクリックのなごり）。Shift + ドラッグで状態を動かします。
- **03 DFA の最小化**：p5.js 版の「（ごみ箱を含む）」の表示は、参照している値がないため一度も出ないので、こちらも出しません。
- **04 正規表現から NFA へ**：後もどりする方法の手数（最大 300 万手）はキーを押したときに 1 回だけ計算します。文字が変わらないキーでは作り直しません。
- **10 チューリング機械**：時空図は 1 手 = 1 行のピクセル画像を縦に 3 倍に引きのばして描きます。
- **11 忙しいビーバー**：2 状態の機械 20736 個の分類は、p5.js 版と同じく 1 フレームに約 4 ミリ秒ずつ（64 個ずつ）進めます。分類の結果は全部の機械で p5.js 版と同じです。
- **12 ゲームの敵キャラ**：視野の扇形は多角形で描きます。
- **14 オートマトンの作曲**：Web Audio の代わりに Art.Sound の `playTone` を使います。雑音や音の高さを下げる音は作れないので、キックは短い 60 Hz の正弦波、スネアは 190 Hz のノコギリ波、ハイハットは 6000 Hz の短い矩形波で近づけます（音量はどれも p5.js 版の音量 × `master` 0.12）。拍は `millis()` ではなく経過時間 `envTime` で計ります。音を ON にする必要がないので、最初のクリックからふつうに状態を足せます。
- **15 身ぶりの認識**：カメラは Art.Device（ffmpeg 経由、64 × 48、左右反転）で読みます。カメラがないときや C で切ったときはマウスの動きを使います。`S` の保存は PNG ではなく SVG です。
