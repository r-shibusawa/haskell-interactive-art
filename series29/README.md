# シリーズ29：待ち行列理論 ─ Haskell コード集

レジ・窓口・コールセンター・道路の渋滞。「ランダムに来る客」と「ランダムにかかるサービス」から行列が生まれるしくみを、シミュレーションと公式の両方で確かめるコード集を、Haskell（gloss）で書きました。

p5.js 版：https://r-shibusawa.github.io/p5-interactive-art/series29/

## 使い方

```
cabal run s29-00
```

番号を変えると別のスケッチ（`s29-01`、`s29-15` など）が動きます。

## p5.js 版との違い

- 画面は 1280×800 の固定で、ウィンドウの大きさには合わせません。画面の文字は英語です（gloss の文字は ASCII のみ）。λ・μ・ρ は lambda・mu・rho と書きます。角の丸い四角は普通の四角になります。
- 04：F の 20 回の測定は、1 フレームに 1 回ずつ進めます（0.3 秒ほどで終わります）。300 分の測定が終わると、次の待ち行列へそのまま進みます。
- 06・13：行列の点は画面に収まる数だけ描きます（06 は 29 人、13 は 27 人まで。残りは +N と表示）。
- 08：↓ で 1 フレームの人数を半分にするとき、端数を切り捨てて整数にします。
- 11：F の基本図は、1 フレームに 1 つの密度ずつ描きます（0.5 秒ほどで終わります）。
- 13：音を出す前のクリックは要りません。音は OS の再生コマンドで鳴らすので、少し遅れ、同時に 8 音までです。「カチッ」はノイズではなく短く高い音です。ドローンは続けて鳴る音ではなく、0.5 秒ごとに鳴らし直す短い音で、ローパスフィルターはかかりません。
- 14：S の保存は PNG ではなく SVG です。窓口の箱の中には使用率を % だけ書きます。1 つの窓口に並べるのは 5000 人までです。
- 15：カメラが使えないときは灰色の四角ではなく、動く合成映像を流します（クリックで数えるのは同じです）。カメラには ffmpeg が必要です。
